Rest steps, editable durations, and where the model comes in

Two decisions from the extraction-pipeline discussion, written up so they're easy to build against: how rest intervals get configured in the review screen, and the shape of the input & extraction pipeline once URL, file upload, and plain text each cover more than one content type — which parts stay deterministic and which one hop is the LLM.

Only rows where auto_generated is true disappear. The hand-inserted 5s rest stays — the switch means "stop auto-filling gaps," not "no rests," so nothing you placed on purpose is ever touched by it.

Settled on adding two booleans to Movement rather than inferring rest from the name: is_rest marks the row as an interval instead of an exercise, and auto_generated is what the toggle checks before deleting anything. A name match (name === 'Rest') would've avoided the schema change, but it breaks the moment a row gets renamed and can't tell an auto-filled gap from one you placed on purpose — which is exactly the distinction the toggle needs.

02 Input & extraction pipeline

Three input types, one model call

Down from four separate fields (video link, video upload, webpage link, PDF upload) to three, since URL and file upload can each carry either kind of content — the app just has to tell them apart. Plain text is new: type "6 reps, 6 seconds each for bridges" straight in, no extraction needed at all.

1URL
One field. A video link (YouTube/TikTok/Instagram/Facebook domain) goes to the existing video pipeline; anything else is treated as a webpage and scraped.
2File upload
One picker. A video file (.mp4/.mov) goes to the existing video pipeline; a PDF is text-extracted, with a scanned-page fallback.
3Plain text
A textarea for typed instructions. Already text — skips routing and extraction, goes straight to the interpretation call.

The video pipeline (grey, already built) and the text pipeline (lime) still end at the same tables. Detecting which of the three inputs needs which treatment is a cheap deterministic check — domain regex, file mime type, page text-density — not a model decision. The only step that isn't plain code is content interpretation: reading "hold 6 seconds, repeat 6 times, 3 sets" and deciding what that means for the move/rest sequence that gets saved.
